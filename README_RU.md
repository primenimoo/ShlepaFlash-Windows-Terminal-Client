# ShlepaFlash — Windows Terminal Client

**Интерактивный терминальный клиент ShlepaFlash** для просмотра каталога сайта, загрузки подходящего файла прошивки и записи ESP32/ESP32-S3 через USB. Интерфейс оформлен в тёмном стиле с бело-оранжевым ASCII-логотипом, анимированным состоянием подключения и поддержкой клавиатуры и мыши в Windows Terminal.

> Важно: скрипт установки и тесты не могут доказать, что произвольная прошивка безопасна для конкретной платы. Перед записью клиент проверяет связь файла с выбранным чипом. Физические устройства не подключены к среде разработки, поэтому аппаратный smoke-test нужно провести на своей плате.

## Возможности

- Получает список моделей и доступных файлов из публичного API: `https://sflasher.bot.nu/api?action=desktop-manifest`.
- Проверяет состояние API: `https://sflasher.bot.nu/api?action=desktop-health`.
- Загружает логотипы прошивок из публичного `https://sflasher.bot.nu/api?action=list`. Это именно поле `logo`, сохранённое в админке; изображения преобразуются в цветные пиксели терминала. Если логотип отсутствует или терминал не поддерживает цвет, выводится текстовый знак.
- Список устройств: M5StickC Plus2, M5StickC Plus, M5StickS3, Flipper Zero, T-Embed CC1101 (список берётся с сайта).
- В каталоге отображаются только те записи прошивок, для которых API опубликовал файл именно для выбранной модели.
- Скачивает файлы по HTTPS в `%LOCALAPPDATA%\ShlepaFlash\downloads`, проверяет HTTP-ответ, размер и формат до записи.
- Показывает обнаруженные COM-порты, VID/PID/описание и обновляет список каждые 5 секунд.
- Для ESP32/ESP32-S3 проверяет магический байт ESP image и ID чипа; не допускает запись образа ESP32 в выбранный ESP32-S3 или наоборот.
- Вычисляет адрес записи в соответствии с правилами используемого на сайте WebFlasher: полный образ с таблицей разделов записывается с найденного начала образа; образ только приложения — по `0x10000` с предупреждением о необходимости совместимого загрузчика.
- Запускает esptool как отдельный процесс без `shell=True`, показывает журнал, прогресс и результат.
- Для Flipper Zero скачивает пакет, предлагает открыть qFlipper и честно передаёт финальный шаг пользователю: выбрать **Install from file / Установить из файла**. Flipper Zero не прошивается через esptool.
- Для T-Embed сырой `.bin` допускается к esptool только если заголовок соответствует ESP32-S3; архив или пакет не передаётся в esptool.
- Кэширует последнюю полученную версию каталога. Без сети каталог можно просмотреть, но скачать и прошить файл без подключения к сайту нельзя.
- Ведёт журнал в `%LOCALAPPDATA%\ShlepaFlash\logs\client.log`.

## Установка на Windows 10/11

Рекомендуется Windows Terminal или PowerShell. Для интерактивного интерфейса нужен терминал с поддержкой Unicode и 24-битного цвета. Цвета не требуют отдельного шрифта: используются стандартный моноширинный шрифт терминала и true-colour последовательности. Можно выбрать Cascadia Mono или другой моноширинный шрифт в настройках Windows Terminal.

### Установка из публичного GitHub-репозитория

1. Создайте публичный репозиторий GitHub, например `ShlepaFlash-Desktop`.
2. Распакуйте содержимое этого ZIP **в корень репозитория**. `README_RU.md`, `install.ps1`, `pyproject.toml` и папка `src` должны лежать на верхнем уровне; не загружайте ZIP как один-единственный файл.
3. Зафиксируйте изменения в ветке `main` (или оставьте стандартную ветку репозитория; установщик определяет имя ветки автоматически).
4. В PowerShell выполните одну команду, заменив `OWNER/REPO` на свой GitHub-владелец/репозиторий:

```powershell
$env:SHLEPAFLASH_REPO='primenimoo/ShlepaFlash-Windows-Terminal-Client'; irm 'https://raw.githubusercontent.com/primenimoo/ShlepaFlash-Windows-Terminal-Client/main/install.ps1' | iex
```

Установщик ставит Python 3.12 через `winget`, только если подходящего Python 3.11+ нет; создаёт отдельное виртуальное окружение; устанавливает зависимости; проверяет импорт библиотек; при наличии `winget` также пытается установить официальный qFlipper для Flipper Zero (сбой этого необязательного шага не отменяет установку ShlepaFlash); добавляет команду запуска `shlepaflash` в пользовательский PATH. Если команда не видна в старом окне, откройте новое окно PowerShell.

> Команда предполагает **публичный репозиторий**. Не запускайте `iex` с произвольных ссылок. Перед публикацией внимательно прочитайте `install.ps1` и устанавливайте только из собственного репозитория.

### Локальный запуск без установки в PATH

В корне репозитория:

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -e .
.\.venv\Scripts\python.exe -m shlepaflash
```

## Использование

1. Запустите `shlepaflash`.
2. На главном экране выберите **Прошивка устройства** стрелками и нажмите Enter либо щёлкните мышью.
3. Выберите модель, затем подходящую прошивку из каталога сайта.
4. Просмотрите описание и нажмите **Выбрать и скачать**.
5. Для ESP32 клиент проверит BIN и чип до открытия COM-порта. Подключите плату USB-кабелем с передачей данных, выберите порт и нажмите **Прошить**.
6. Подтвердите начало записи. Не отсоединяйте плату во время записи.
7. После завершения проверьте перезапуск устройства. На некоторых платах может потребоваться нажать Reset.

Клавиши: `↑`/`↓` — перемещение, `Enter` — выбор, `Esc` — назад, `Ctrl+R` — обновить каталог на главном экране, `Ctrl+Q` — выйти. Пункты интерфейса также поддерживают мышь.

## Логотипы прошивок из админки

Текущий `desktop-manifest` не включает бинарное поле `logo`. Поэтому клиент делает дополнительный запрос к уже существующему `GET /api?action=list`, в ответе которого каждая прошивка содержит публичное поле `logo`. Поддерживаемые растровые логотипы (например, PNG, JPEG, WebP и GIF) преобразуются через Pillow и отображаются как небольшой true-colour рисунок из цветных блоков терминала. SVG и неподдерживаемые/повреждённые изображения показываются как текстовые инициалы; приложение не пытается скачивать внешние изображения по URL. Если логотип не удалось загрузить/декодировать, приложение не падает — вместо картинки отображаются первые буквы названия.

Это не меняет сайт и не требует добавлять API-ключ: приложение использует только публичные read-only endpoints. Если позже API `action=list` перестанет отдавать `logo`, будут использованы текстовые знаки.

## Как работает прошивка

### ESP32 и ESP32-S3

Используется официальная библиотека Espressif esptool, установленная в изолированное Python-окружение. Перед запуском процесс получает `--chip`, COM-порт, адрес записи и путь к проверенному файлу. Пользователь должен подтвердить запись. В проекте нет автоматического стирания всей Flash-памяти и нет `--erase-all`.

Необходимо выбирать прошивку, опубликованную администратором именно для подключённой модели. Если BIN загружен в неверный слот сайта или в нём нет ожидаемого заголовка, клиент останавливается до записи. Отсутствие таблицы разделов распознаётся как возможный image только приложения; такое изображение требует уже установленного совместимого загрузчика.

### Flipper Zero

Flipper Zero использует собственный протокол обновления. Клиент скачивает опубликованный пакет и предлагает открыть официальный qFlipper. Дальше нужно выбрать **Install from file** и вручную указать пакет. Это намеренно не маскируется под автоматическую запись через esptool.

Официальная информация: [обновление Flipper Zero](https://docs.flipper.net/zero/basics/firmware-update), [qFlipper](https://docs.flipper.net/zero/qflipper).

## API сайта

- Health: `GET /api?action=desktop-health`
- Manifest: `GET /api?action=desktop-manifest`
- Catalog alias: `GET /api?action=desktop-catalog`
- Public logo metadata: `GET /api?action=list`
- Firmware download: `GET /api?action=download&id={firmwareId}&model={deviceId}`

Клиент не использует админские токены, не изменяет каталог и не отправляет данные на сервер, кроме обычных GET-запросов для health/каталога/загрузки.

## Тесты

После установки development-зависимостей:

```powershell
py -3 -m pip install -r requirements-dev.txt
py -3 -m pytest -q
py -3 -m compileall -q src tests
```

Тесты покрывают схему манифеста, точное соответствие модели download record, запрет сторонних download URL, безопасные имена файлов, заголовки ESP32/ESP32-S3, выбор адреса для образа только приложения и отказ при неправильном чипе/HTML/ZIP вместо BIN. CI выполняет синтаксические проверки и unit tests при каждом push/pull request.

Аппаратный тест требует реальной платы и правильного BIN: подключите устройство, убедитесь, что выбран правильный COM-порт, и выполняйте запись только на собственном устройстве.

## Диагностика

- Главный журнал: `%LOCALAPPDATA%\ShlepaFlash\logs\client.log`
- Скачанные файлы: `%LOCALAPPDATA%\ShlepaFlash\downloads`
- Кэш каталога: `%LOCALAPPDATA%\ShlepaFlash\cache\catalog.json`
- Удаление команды запуска: запустите `uninstall.ps1` из репозитория. Он удаляет команду из PATH, но оставляет кэш, журналы и скачанные файлы.

## Безопасность

- Не запускайте BIN, архивы или исполняемые файлы, загруженные из неизвестного источника.
- Не прошивайте устройство, если его модель/чип не совпадает с прошивкой.
- Не отключайте USB во время записи.
- Публичная часть API используется только для чтения; секреты сайта в клиенте не нужны и не должны добавляться.
- Если прошивка содержит исследовательские функции беспроводной связи, используйте их только на собственном оборудовании и в сетях, где есть разрешение.
